# Repository Rules

- Keep repository policy, onboarding, terminology, validation guidance, plans, and working memory under `.aisteering/`.
- Preserve project-owned content. Treat generated installations and provider discovery as disposable local state.
- Keep `.aisteering/LANGUAGE.md` aligned with current code and contracts.
- Add project-specific validation commands to `.aisteering/VALIDATION.md` before claiming behavior works.
- Keep `.aisteering/PROJECT.md` aligned with authority locations and lookup procedures. Resolve current status from those authorities instead of copying it into configuration or handoffs.
- Record mutable unresolved cross-session notes in dated files under `.aisteering/scratchpads/`.
- Record an end-of-substantive-turn retrospective under `.aisteering/summaries/`; archive completed or stale notes rather than leaving them active.
- Select scratchpads and summaries by task, topic, affected path, or decision. Never read either directory wholesale.
- Record any approved default or fallback as a narrow entry in `.aisteering/policy-exceptions.md`.
